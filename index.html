它解决什么问题

PROBLEM

很多 SaaS 系统（如 OA、CRM、审批中心）习惯用 window.open 弹出独立小窗，而不是在浏览器里开一个新页签。当窗口一多，麻烦就来了：

😣 改造前：满屏飘浮窗

窗口互相遮挡、任务栏难找、Alt+Tab 切换成本高；最小化后容易「找不回」正在处理的单据。

😊 改造后：整齐标签页

所有内容收进同一窗口的页签，Ctrl/Cmd+数字 或点击即切换；关闭、收藏、搜索一气呵成。

💡 适用场景：公司 SaaS OA、审批流、各类「新开窗体」的 Web 系统——尤其当系统无法做二次开发（SaaS 模式）时，用浏览器扩展从客户端侧解决，是成本最低、风险为零的办法。

它怎么做到的

HOW IT WORKS

页面的「新开窗」本质是 JS 调用 window.open(url, name, features)——第三参数（宽高、坐标）才是弹出独立窗口的元凶。扩展在页面脚本执行前接管该函数，把第三参数丢掉，浏览器便默认走新页签。被访问站点完全无感知。

① 页面触发

window.open 被调用

站点 JS 执行 window.open(url,'_blank','width=900,height=600')

→
② 扩展拦截

丢弃 features 参数

主世界脚本接管 window.open，只保留 url 与 name，第三参数清零

→
③ 浏览器默认

新页签打开

没有 features 指示弹窗，浏览器按默认行为在新页签打开

🔒 安全与兼容：窗口名（name）被保留，所以站点里「同一单据复用窗口」的逻辑在页签模式下依旧成立；非 http/https 地址不触碰；只拦截 window.open，不影响页面其它功能。

带来什么便利

BENEFITS

全局自动生效

所有网站的弹窗自动转页签，装上即用，无需逐站配置。

白名单例外

网银控件、扫码登录、打印预览等确需弹窗的站点，加入白名单即保留原生窗口。

一键开关

点扩展图标即可启用 / 暂停，临时想保留弹窗时关掉即可，无需卸载。

可视化配置

弹窗卡片 + 详情页「扩展程序选项」双入口，点几下就能管理白名单。

即时生效

白名单改动实时保存，页面无需重启；可一键刷新当前页让规则立即应用。

跨浏览器

Chrome / Edge / 豆包 / 360极速 / QQ 等 Chromium 内核浏览器通用。

白名单怎么配

WHITELIST

白名单里的站点会保留原生弹窗（不转页签）。配置完全在插件界面里完成，不写死在代码里。两种方式进配置：① 点工具栏图标 → 弹窗中的「保留原生弹窗的网站」卡片；② 详情页 →「扩展程序选项」按钮（全屏配置页）。
